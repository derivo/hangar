# Review: ADR 0046 (inbox, activity log) and ADR 0047 (workers), 2026-11-16

Reviewer: Codex (read-only), design review of both proposed ADRs against the
code. All eight findings were accepted; the ADRs carry them as "Corrections from
the design review".

1. **[P1] `task.done` stores foreign text outside the inbox**, and notes keep
   only a display name (`bays/board/src/main/board.ts:90`). → All text inputs
   are inbox functions; origin per text from the authenticated caller.
2. **[P1] Leases and outbox need an identity per attempt**; a late `done` could
   close a reopened task. → `claimId` and revision checked atomically.
3. **[P1] Two slots of one worker could claim the same task**: the relay sends
   no session, and `claim` lets the same holder claim again
   (`board.ts:79`). → Claim only from `open`, per attempt.
4. **[P1] `accept(id)` had no state between approval and side effect.** →
   Persisted state machine with execution id; handlers deduplicate.
5. **[P1] Trust gives no outgoing call path**: `ctx.call` allows only `uses`
   targets (`packages/host/src/bay-runtime.ts:175`), the bus asks without a
   grant, a headless server cannot answer. → Remote `uses` entry resolved by
   fingerprint, grant provisioned at setup.
6. **[P1] The password bay does not run on the server**
   (`apps/server/src/server.ts:225`). → Environment file of the service.
7. **[P2] Ordered delivery is not ordered execution** when a note is queued. →
   Trusted calls execute at once; one atomic `task.finish`.
8. **[P2] A restored session is no proof of a running agent**
   (`bays/agents/src/main/sessions.ts:152`). → Persistent run record per phase.
