# Review: ADR 0041, server on a Linux machine set up over SSH (2026-11-11)

Reviewer: Codex (read-only), before the commit. Scope: the new ADR 0041 against
the code (`apps/server`, `packages/bridge`, `bays/agents`, `docker/server`) and
ADRs 0019, 0029, 0036.

## Findings

1. **[P1] Data folder not protected.** Only the runtime was 0700; sessions and
   scrollback are written with default modes. Accepted: the whole
   `~/.local/share/hangar` is 0700 and the unit sets `UMask=0077`.
2. **[P2] `~` in the unit.** systemd and `parseOptions` expand no tilde.
   Accepted: `%h` and absolute paths.
3. **[P2] Architecture is not binary compatibility.** node-pty built on a newer
   glibc fails on older systems. Accepted: baseline is the glibc of the
   Docker build image, checked before upload, minimum measured in step 1.
4. **[P2] Package layout unspecified.** Without `--bays`/`--cli` the server
   assumes the repository (`apps/server/src/options.ts`). Accepted: fixed
   layout, explicit paths.
5. **[P2] Build not reported.** The bridge knows the protocol version, `/health`
   the package version only. Accepted: the build is read over SSH from the
   runtime folder the unit starts; works without a bridge connection.
6. **[P2] Service environment differs from the terminal.** A user service reads
   no profile; Linux sessions start without login. Accepted: `PATH` from the
   login shell at setup into an `EnvironmentFile`, `git` checked.
7. **[P2] Journal not readable for every user.** Accepted: output appended to
   `<data>/server.log` instead of the journal.
8. **[P3] Lingering does not always need root.** Accepted: depends on polkit;
   the command is shown, `sudo` only if the policy requires it.
9. **[P3] Login command.** The ADR named a concrete command; replaced by "the
   client's own login flow" so the ADR does not depend on a client's CLI.
