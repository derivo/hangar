# Review draft ADR 0036 – shells survive a restart (2026-11-03)

Reviewer: Codex (`codex exec -s read-only`) against the code. Subject: draft
with a separate process `pty-host` for the shells of the agent bay, the same
MCP port and tokens that persist.

## Findings (excerpt, not implemented)

- **P1:** Claude Code gives up the MCP connection after limited retries; if
  Hangar stays closed longer, the Hangar tools are missing despite the same
  address. MCP also listens before the tokens are restored (401).
- **P1:** An occupied port forces a restart of the agent after all; a foreign
  service on the port would get valid tokens.
- **P1:** The Windows installer (NSIS) ends all processes in the installation
  folder, hence also a `pty-host` from `Hangar.exe`.
- **P1:** The secret at the socket only checks the client, not the host
  (Windows pipe names, old sockets, symlinks).
- **P1:** Ending orphaned shells according to `state.json` kills agents if the
  shell started before saving or the state is damaged.
- **P2:** Incompatible old hosts, environment for jobs after reconnecting,
  status from hooks while Hangar is closed, terminal state on attaching,
  confirmation of start and end via the socket, jobs after a crash, process
  setup in the container.
- **P3:** Same PID and `hangar status` do not prove a reconnected MCP
  connection.

## Alternative

Run the existing `hangar-server` (ADR 0019, 0029) locally as a background
service; the desktop pairs over loopback as with a remote server. Bays, MCP,
tokens, scheduler and shells then live in the server and survive quitting,
updating and crashing of the desktop app. Restart and update of the server
itself remain open. tmux/dtach solve only the shells under POSIX, not MCP and
not Windows.

## Second round: local server

Decision of the person: local server. Codex checked the second draft against
the code; incorporated into ADR 0036:

- **P1, fixed in the code:** A broken WebSocket frame before login ended
  `hangar-server` (no `error` handler in `bridge.ts`). Test
  "survives a broken frame before any login" was red before (unhandled
  `WS_ERR_EXPECTED_MASK`).
- **P1:** The server file alone is not enough (paths to bays and CLI relative to
  the repository); an update replaces files that the hooks and node-pty load
  later; the app requires the same bay version for the UI. → runtime copy per
  version, explicit paths, UI from the copy (points 1, 5).
- **P1:** A return channel for desktop bays extends the trust boundary. → only
  the local server, own caller kind and own subject (point 7).
- **P2:** Move without jobs, permissions, settings; no unambiguous owner after
  a failed start; occupied port after restoring the shells;
  `ELECTRON_RUN_AS_NODE` in session environments; no workspaces in the server.
  → points 3, 5, 8, 9, 11.
- **P3:** Pairing code atomic per switch, log path protected, acceptance with a
  real quit, `kill -9`, replaced bundle and a long agent run. → points 2, 4,
  implementation.
