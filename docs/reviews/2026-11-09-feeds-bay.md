# Review: feeds bay (2026-11-09)

Reviewer: Codex (gpt-6.1-sol, read-only), before the commit. Scope: the
uncommitted feeds bay on `feat/rss-bay` (ADR 0040): `bays/feeds`,
`IN_SERVER` in `apps/desktop/src/main/index.ts`, `e2e/feeds.spec.ts`, the feeds
step in `e2e/local-server.spec.ts`, docs. Codex reproduced its findings in
memory; the repository tests and E2E were not run in its sandbox.

## Findings

1. **[high] SSRF through `feed.add`.** An agent could subscribe to loopback,
   private or metadata addresses, and the fetch follows redirects. **Fixed for
   agents** (decision of the person: only agents are limited): `feed.add`
   rejects `localhost`, `*.localhost`, `*.local`, `*.internal` and loopback,
   private, link-local, shared and unspecified IPv4/IPv6 ranges with
   `node:net` `BlockList` (also IPv4-mapped IPv6 and numeric IPv4). Test
   `feed.add keeps agents away from the own machine and private networks`.
   **Accepted limit:** only the literal host is checked; a public name that
   resolves inward, or a redirect, still passes. The person may subscribe to
   local feeds in the UI.
2. **[medium] Unbounded response size.** **Fixed:** the main part reads the
   body in pieces and stops at 5 MB with `Feed too large`. Test
   `stops reading a feed larger than 5 MB`.
3. **[medium] Entries that dropped out of the history came back.** **Fixed:**
   `feeds.json` keeps the ids of each feed's last fetch (`seen`). Test
   `does not bring back entries that dropped out of the history while the feed lists them`.
4. **[medium] A feed with more than 1000 entries was rejected as a whole.**
   **Fixed:** the parser keeps the newest 1000. Test
   `keeps the newest 1000 entries of a long feed`.
5. **[medium] `since` compared ISO strings.** **Fixed:** `since` must be an ISO
   date-time with `Z` or offset and is compared as a time. Test in
   `feed.items returns the newest items, filtered by feed and time`.
6. **[medium] Unsubscribe and subscribe again during a fetch skips the
   immediate fetch.** **Accepted:** the next refresh (button or 15 minutes)
   fetches it; noted in ADR 0040.
7. **[medium] No auto-scroll once the history is full.** **Fixed:** the scroll
   follows the newest entry, not the count. No unit test (jsdom has no layout).
8. **[medium] Atom text was read as HTML.** **Fixed:** only Atom
   `type="html"` and RSS descriptions are parsed as HTML. Test
   `keeps Atom text as text and reads XHTML content`.
9. **[medium] Atom `xml:base` ignored.** **Accepted:** rare; links resolve
   against the feed URL. Noted in ADR 0040.

## Second round: settings dialog

Reviewer: Codex (read-only), on the settings dialog (`feeds.ts` `configure`,
the `settings` handler, `SettingsDialog` in `App.tsx`, `api.ts`, the settings
part of `feeds.spec.ts`).

1. **[P2] A save that ended after the dialog closed closed a dialog opened
   since.** **Fixed:** the dialog acts on a save's result only while it is
   still open. Test `a save that ends after the dialog was closed leaves a
reopened dialog open`.
2. **[P2] `configure` changes the state before writing; a failed write keeps
   the change in memory.** **Accepted:** `add`, `remove`, `ingest` and
   `failed` work the same way; a disk that cannot write breaks the bay
   either way.
3. **[P3] The e2e form matrix lacked empty fields, fractions and values above
   the maximum.** **Partly fixed:** `index.test.ts` already checks both fields
   with 0, above the maximum, fractions and text, each with its exact
   message; the e2e now adds an empty field for each.
