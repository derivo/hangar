# apps/desktop

Electron app: window with a sidebar on the left, one `WebContentsView` per bay, bay loader,
bay runtime (context for the main part), IPC between bays and main process.

## Structure

- `src/main/index.ts` – start, single instance, quit flow.
- `src/main/host.ts` – window, bay views, IPC (`shell:*`, `bay:*`), tray, notifications, app badge.
- Bay loader, bay runtime, `settings.json`, CLI shim and `startCore` (bus, MCP, scheduler) live in `@hangar/host` (`packages/host`, without Electron); the app adds window, dialogs, tray and notifications.
- `src/main/browser-tabs.ts` – host module `browser` (ADR 0015): one `WebContentsView` per tab, partitions `bay-browser:<bay-id>:<name>`, no permissions for web pages, only http/https/`about:blank`, loading at most 30 s. Zoom keys of a page (Cmd/Ctrl +, =, -, 0, level ±0.5 like the app menu) are handled in `before-input-event`, so `onChange` reports `zoom`; the menu would not tell (E2E sends them with `sendInputEvent`, Playwright's CDP keys skip that event). Hidden tabs lie invisible in the main window (1280 × 800, so that screenshots have content); `bay:browser.show` places a tab over a rectangle of the calling bay view or its window.
- `settings.json` (`@hangar/host`): update channel, language, color scheme → `nativeTheme.themeSource` (IPC `shell:theme`), bays of the sidebar `bays` (ADR 0017), settings of the bays `baySettings` (ADR 0023; IPC `shell:baySettings`, `shell:baySetting` only for declared keys with the type of their `default`, afterwards `runtime.settingChanged`; `text` as a text field, ADR 0025); `src/main/updates.ts` – electron-updater (packaged only), `updaterOptions`.
- Server bays (ADR 0019, part 10b): `host.ts` holds `ServerConnections` (`<userData>/servers.json`); every bay of a connected server becomes a `BayTarget` with key `remote:<server-id>:<bay-id>`, UI from the local bundle, `bay:invoke` over the connection. IPC `shell:server.probe`, `shell:server.pair`, `shell:server.cancel`, `shell:serverMenu`; pairing in the plus modal (`ServerPairing` in `Sidebar.tsx`). Permission questions of a server are shown by `askWithDialog(request, servername)` (`prompter.ts`) with "On the server …" before the text. Notifications of a server go to `notify(remote:<server-id>:<bay-id>)` with "<server name>: " before the title; `ServerConnections` gets the language of the app (`services.locale`) for `auth`/`pair`; badges of the server bays are in `ServerView.badges` and count on the app icon too (`setAppBadge`). `jobs()` returns the jobs of connected servers as `servers` (groups in `Jobs.tsx`); `shell:job.*` optionally take the server id. The preload asks `bay:server` synchronously (server name via `event.sender`, local `null`) and sets `window.hangar.server`.
- Order of the sidebar (ADR 0038): `order()` in `host.ts` sorts bays of the app and of the local server together by `settings.json` `bays` (`ShellState.order`); IPC `shell:moveBay`/`shell:moveShortcut` (id and index), menu entries "Move up"/"Move down" in `bayMenu` (also for bays of the local server) and `shortcutMenu`. Dragging: `useReorder` in `Sidebar.tsx`, one instance per list. E2E `e2e/sidebar-order.spec.ts`.
- Shortcuts (ADR 0027): `settings.json` `shortcuts` (`@hangar/host` `shortcuts.ts`: `shortcutUrl` checks http/https, `validShortcuts` on reading). IPC `shell:shortcut.pick` (file dialog, `file`/`folder`), `shell:shortcut.url`, `shell:shortcut.open` (id only; `shell.openPath`/`openExternal`, errors as `showMessageBox`), `shell:shortcutMenu`. `host.ts` loads icons once per target (`createThumbnailFromPath`, on Linux `getFileIcon`). E2E: `e2e/shortcuts.spec.ts` replaces file dialog, `shell.openPath`/`openExternal`, `showMessageBox` and context menu.
- Workspaces (ADR 0030): without a local server `index.ts` creates `Workspaces` (`<userData>/workspaces`, key via `safeStorage`, without a keychain `plain:`, or `pass:` with `HANGAR_KEY_PASSPHRASE`; E2E with `use-mock-keychain`) and passes them as `remote` to `startCore`. With a local server it holds them (ADR 0036, item 11): the move brings the folder along (`keys` to `migrateToLocalServer`/`migrateFromLocalServer`), the IPC calls go via `Host.localWorkspaces` to it. IPC `shell:workspaces`, `shell:workspace.{connect,create,invite,join,accept,reject,remove,share}` → `workspaceAction`, event `shell:workspaces`; settings in `src/renderer/Workspaces.tsx`. E2E `e2e/workspaces.spec.ts` starts `apps/relay/dist/hangar-relay.mjs` and two instances.
- Installed bays (ADR 0034): `index.ts` creates `BayStore` (`<userData>/packages`), calls `applyPending` before `Host` (resets `allow` permissions of newly sensitive functions) and passes `bayDirs()` to `Host` (`bayRoots(installed)`). IPC `shell:bay.{catalog,prepare,confirm,cancel,rollback}`; `confirm` puts a new bay into the sidebar. UI `src/renderer/BayCatalog.tsx` (confirmation via `window.confirm` with permission diff). E2E `e2e/bay-install.spec.ts` with a local index and four starts.
- `src/main/local-server.ts` – local server (ADR 0036, step 1): `ensureLocalServer` copies the packaged app once per build via `ditto` to `<userData>/local-server/runtime/<version>+<build id>` (`copyName`: 8 characters of the SHA-256 of `Info.plist` – its `ElectronAsarIntegrity` hashes `app.asar`, whose own stat is a virtual folder inside Electron –, `server/hangar-server.mjs`, `cli/hangar.mjs`, the `Info.plist` of `Electron Framework.framework` (Electron version) and, if signed, `_CodeSignature/CodeResources`; without any of them only the version) (unpackaged: Electron, `apps/server/dist`, first bay folder and CLI of the repository), writes the plist `dev.hangar.server.<8 characters of the SHA-256 of the data folder>` (`ELECTRON_RUN_AS_NODE`, `RunAtLoad`, `KeepAlive`, log `<data>/server.log`) and loads it with `launchctl bootstrap` (after a `bootout` it first waits until `launchctl print` no longer finds the service, at most 30 s: `bootout` returns while the old server still ends, and launchd refuses a load until then with exit code 5; a failed load throws instead of leaving the service unloaded). A plist whose copy is still there stays (the server keeps its version); copies that no plist names are deleted. `pairWhenReady` repeats `Host.pairLocalServer` until the server answers. `index.ts` calls both after `host.start()`. Step 2: `migrateToLocalServer(o, bayId)` runs in `index.ts` before `startCore` (otherwise bus and scheduler would already have loaded `permissions.json`/`jobs.json`), stops a loaded service (`stop`: after `bootout` it waits like the restart until `launchctl print` no longer finds the service, at most 30 s, else it throws like a failed `bootout`; so the old server no longer writes into the moved data and a later `ensureLocalServer` loads it again) and moves bay data, jobs of the bay, permissions with target `<bay>/…` and `baySettings[<bay>]`; every part is repeatable, the marker `migrated` comes last. Permissions of the agent bay on bays of the app stay in the app and get the subject `local-server:<bay>` (step 3). Step 3: `Host` gives `ServerConnections` the listener `local`: `functions` are the bus functions of the bays started here, `call` allows only their targets and calls the bus with caller `{ kind: 'local-server', bayId, sessionId? }` (built field by field), `sessionEnded` ends the session in the bus and reports it to the bays with `bayId` `local-server:<bay>`; after `addBay`/`removeBay` `offerAgain()`. `Host` gets `localServer: { owns, uiRoots }`: bays in `owns` are neither started nor offered by the app; `serverUiRoots` names the bay folders of the runtime copies from which `localBundle` loads the UI of the server version. Bays of the local server (`ServerView.local`) have no `server` (no path form); `project.add` without a path shows `pickFolder` and passes the path on. Step 4a: bays of the local server are in `ShellState.localServer` (not in `servers`), label without server name, notifications without prefix. If it is not connected, the bays come from `owns` and `App.tsx` shows "Local server is not running" (IPC `shell:localServer.restart`, `shell:localServer.log`). An error stays until the next connection (`localError`), "Local server is starting …" only during `restartLocalServer` (no flicker on retries). `localServer.version()` (from `ensureLocalServer`, path of the plist) ≠ `localServer.ready()` (the build of this app, else the app version) → notice above the bay (plain versions when they differ, with build id for a new build of the same version), the view moves down by its height (`UPDATE_HINT_HEIGHT`, until the shell reports the measured height via `shell:hintHeight`; CSS pixels × zoom). While a restart runs (`localStarting`) the state carries `restarting` and the hint shows "Local server is starting …" (`role="status"`) instead of its button, also while the old server is still connected. While the page of a selected local bay says it is down (also during a restart), `followLog()` follows `localServer.log` with `tailFile` (`src/main/log-tail.ts`, own `statSync` polling every 250 ms – not `fs.watchFile`, whose late first stat misses lines written right after the first read –, last 200 lines) and the state carries `log`; leaving the page or quitting stops it. A file that shrinks counts as cut and is read from its start; one cut and grown back to at least its old size between two polls goes unnoticed (accepted: launchd only appends to `server.log`). A cut-off line start is dropped, a line without an end keeps only its last 64 KiB (prefixed `…`). "Log anhalten"/"Pause log" (`aria-pressed`) holds the lines shown (WCAG 2.2.2); the log follows new lines only while scrolled to its end. `retry` is the reconnect attempt from `ServerView.retry` (the next one already during the pause; gone once no attempt follows; shown as a polite `role="status"`). Restart: `ensureLocalServer(o, true)`, then `pairLocal` (reconnects a paired server, also after a rejected version); confirmation prompt, unless the connected server reports 0 shells; clicks during a restart attach to it, an error comes as a message. Tray shows `sessions`. Step 4b: `localServerWanted` (macOS; variable before `settings.json` `localServer` before "packaged"); off → `migrateFromLocalServer` before `startCore` (stop service, delete plist and `runtime/`, bay back, subject back, `servers.json` without the local entry, win rules of the agents from the server; marker `returning` on the way; if it fails, the bay runs in the server as long as the marker `migrated` is there (stopping failed), otherwise where its folder is, `bayInLocalServer`). IPC `shell:localServer.setting` (with `forced` when the variable decides: switch disabled), `shell:localServer.enable`, `shell:relaunch`; switch in `Settings.tsx`. E2E `e2e/local-server.spec.ts` loads a real LaunchAgent and unregisters it at the end with `launchctl bootout`.
- Host module `secrets` (ADR 0021): `index.ts` provides `services.secrets` with `safeStorage` (Base64; without a keychain it throws `t.noKeychain`, never plaintext). With a local server the bays in `IN_SERVER` (agent bay and board) run there; `migrateToLocalServer`/`migrateFromLocalServer` take a list `bayIds` for this. Bundled: `bays/secrets`, `bays/board` (`electron-builder.yml`).
- `src/main/view-state.ts` – `view.json`: window position, "maximized", chosen bay and open bay windows (ADR 0010); stored on quit, restored on start (window position only if its center lies on an existing screen).
- `src/main/overview.ts` – global Git identity (`git config --global`) for the Hangar overview (`shell:overview`, `src/renderer/Overview.tsx`; opened via the Hangar mark at the top of the sidebar; also shows the Hangar version and the bays).
- `src/messages.ts` – texts of the shell (main and renderer) in German and English (ADR 0009).
- `electron-builder.yml` – packages for macOS/Windows/Linux, bundled bays, CLI, node-pty unpacked.
- `src/preload/bay.ts` – `window.hangar` for bays; `src/preload/shell.ts` – `window.hangarShell` for the shell.
- `src/renderer/` – React UI of the shell (sidebar, settings; permissions in `Permissions.tsx` via `shell:permissions`, `shell:setGrant`, `shell:revoke`; jobs in `Jobs.tsx` via `shell:jobs`, `shell:job.pause`, `shell:job.run`, `shell:job.remove`, reloaded on the event `shell:jobs`).
- `index.ts` starts the core with `startCore({ dataDir: userData, … })` (prompter: `dialogPrompter`, CLI shim with Electron in Node mode), passes `core.services` to `Host` and starts the scheduler after `host.start()` (ADR 0013); on quit `host.stop()`, then `core.close()`.
- `e2e/` – Playwright tests against the built app (`out/`).
- Unit tests of the main process: `host.test.ts` replaces `electron` and `@hangar/bridge` with fakes, the bay runtimes are real (test bays with `main.mjs` in the temporary folder, start can be held with `hold(id)`); `browser-tabs.test.ts` with a fake `WebContentsView`; `src/preload/preload.test.ts` checks every method and that every channel in `host.ts`/`index.ts` is registered with the matching kind (`handle`/`on`). Main process and preloads are in the coverage gate, `index.ts` is not (wiring only, E2E).

## Environment variables

| Variable                   | Effect                                                                                                                                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `HANGAR_USER_DATA`         | Own data folder (tests, parallel instances); without it package "Hangar Dev"                                                                                                                                                                                       |
| `HANGAR_BAYS_DIR`          | Bay folder (path list), replaces the default `bays/`                                                                                                                                                                                                               |
| `HANGAR_E2E_EXECUTABLE`    | E2E only: test the packaged app instead of `out/`                                                                                                                                                                                                                  |
| `HANGAR_E2E`               | Only record notifications; window invisible, without focus and Dock icon                                                                                                                                                                                           |
| `HANGAR_E2E_SHOW`          | Only with `HANGAR_E2E`: show the window after all (debugging)                                                                                                                                                                                                      |
| `HANGAR_LOCALE`            | Force the language: `de`, `en` or pseudo-locale `en-XA` (ADR 0009)                                                                                                                                                                                                 |
| `HANGAR_BAY_INDEX`         | Bay index (`index.json`, https or local path) for "Install bays"                                                                                                                                                                                                   |
| `HANGAR_BAY_INDEX_KEY`     | Public Ed25519 key of the index (JWK `x`), only with `HANGAR_BAY_INDEX`                                                                                                                                                                                            |
| `HANGAR_SSH`               | `ssh` command for server tunnels (E2E: `packages/bridge/fixtures/fake-ssh.mjs`)                                                                                                                                                                                    |
| `HANGAR_LOCAL_SERVER`      | `1`/`0`: local server on/off, before setting and default (ADR 0036, macOS only; default only packaged, E2E `0`)                                                                                                                                                    |
| `HANGAR_LAUNCH_AGENTS`     | Folder of the plist instead of `~/Library/LaunchAgents` (E2E)                                                                                                                                                                                                      |
| `HANGAR_KEY_PASSPHRASE`    | Without a keychain: encrypt new relay keys with it (`pass:`, ADR 0030 addendum); taken out of the environment after reading (`takePassphrase`), put back before the in-app relaunch; keys it cannot open → error box, start without workspaces, identity untouched |
| `HANGAR_LOCAL_SERVER_ROOT` | `--root` of the local server instead of the home folder (E2E); with `HANGAR_E2E` the service also inherits `SHELL`, `HOME`, `TMPDIR`                                                                                                                               |

## Pitfalls

- Closing the window only hides it (`host.quitting` only in `before-quit`).
- Icons: sources are `build/icon.svg` (app) and `resources/tray.svg` (tray, black only); `node scripts/make-icons.mjs` renders `build/icon.png` and `resources/trayTemplate*.png` from them with Playwright's Chromium. The suffix `Template` lets macOS adapt the tray icon to the menu bar mode. The Hangar mark of the sidebar is inline in `Sidebar.tsx` (color `--hangar-color-dock-glow`).
- `e2e/a11y.spec.ts` checks shell, settings, agent bay and board with axe (WCAG 2.2 AA, light and dark), plus empty tree, error message, ended shell and 200 % zoom (no horizontal overflow).
- Playwright emulates `prefers-color-scheme` itself; whoever wants to check what `nativeTheme` sets calls `page.emulateMedia({ colorScheme: null })` beforehand (`e2e/theme.spec.ts`).
- E2E tests run against `out/` – run `pnpm build` first (`pnpm test:e2e` does that).
- E2E tests start with `HANGAR_LOCALE=de` (`e2e/helpers.ts`); `e2e/i18n.spec.ts` checks English, the switch and the pseudo-locale.
- Bay views are sandboxed; bays have no Node access, only `window.hangar`.
- IPC from bays is mapped to the bay via `event.sender` – never trust a bay id from the message. This also applies to bay windows (`bay:window.*`, `targetFor`).
- E2E permissions: `e2e/fixtures/vault` is a second bay with a main part (`main.mjs`) that agents call via `curl` on `$HANGAR_MCP_URL`; the permission dialog is replaced via `dialog.showMessageBox` (`e2e/permissions.spec.ts`).
- Only bays from `settings.json` `bays` run (ADR 0017). `host.addBay`/`removeBay` via `shell:addBay` and the native context menu (`shell:bayMenu`); while the selection modal is open (`shell:modal`), `layout()` hides bay views and tabs, otherwise they would cover it.
- E2E: `launch` enters all bays from `bayDirs` into the sidebar in new data folders and selects the first; `seedBays: false` starts empty like a new Hangar (`e2e/sidebar-bays.spec.ts`, replaces `Menu.buildFromTemplate` for the context menu).
- E2E: `repoBays` loads agent and browser bay. Browser functions are `openToAgents` (ADR 0016); `e2e/browser.spec.ts` counts permission dialogs and expects none.
- If an agent session ends (`unregisterAgentSession`), `host.ts` calls `agentSessionEnded` on every runtime (→ `ctx.onAgentSessionEnded`).
- On quit the server connections close after the window; `syncRemotes` then aborts (otherwise "Object has been destroyed").
- E2E: `e2e/server.spec.ts` starts `apps/server/dist/hangar-server.mjs` as a child process and reads address, fingerprint and code from its log. On restart pass `seedBays: false`, otherwise `bayPage` finds the local agent bay instead of the server's.
- E2E: a bay window has the same URL as the view plus `?window=<key>`; `bayPage(app, 'index.html?window=')` finds it.
- Unit tests: a rejection from a `vi.fn` never counts as unhandled (`vi.fn` attaches a handler itself); whoever checks unhandled rejections passes a plain function as the fake (`bays/browser/src/ui/App.test.tsx`).
- E2E: specs import `test`/`expect` from `./helpers`, not from `@playwright/test`: the auto fixture `noPageErrors` makes every test fail in which a page of the app throws an unhandled error or an unhandled rejection (`pageerror`).
- Multi-click (ADR 0028): actions lock per key until the answer; buttons that create, run, open or delete ignore `event.detail > 1`, send buttons via `preventDefault()`. `e2e/chaos.spec.ts` presses buttons with `click({ clickCount: 5 })`; `e2e/fixtures/slow` (`slowBays`) is a bay whose start takes 500 ms and which counts its starts in `globalThis.__slowActivations`.
